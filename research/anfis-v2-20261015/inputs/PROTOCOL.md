# Counterfactual delay experiment protocol

This is an offline controller-only, assumption-based point-queue backtest. The deployed ANFIS ONNX weights are unchanged. It does not run YOLO, modify the production app, actuate a real signal, or establish field causality.

## Sources and split

Use FLUID FIDRT public trajectory, route, and signal CSVs (Figshare article 29974954, derived archive file 64179082). Fit queue discharge parameters on 20250120 only. Hold out 20250525 and 20250526 for baseline validation and controller comparisons. Source files and model are hashed.

Primary scope: east/west straight-through motor vehicles with author-provided intersection entry times and green/yellow entry labels. Car/van map to car and truck/bus/trailer to heavy vehicle. The route table excludes mopeds; therefore this is NOT a mixed-motorcycle validation. Right/left/U turns, pedestrians, signal-violating entries, and vehicles without an author-provided completed route are outside this primary model. Exclusion counts must be reported.

## Fixed assumptions before outcomes

1. Define a 45 m observation corridor upstream of each east/west intersection entry plane. Planes are estimated geometrically per recording from the supplied metric positions at author-labeled entry times. This is an intersection-entry boundary, not independently surveyed stop-line geometry.
2. Eligibility for scoring requires a visible crossing of the 45 m boundary, moving speed >=2 m/s at that crossing, and recorded entry later than inferred free-flow readiness. Background vehicles first seen inside the region initialize/enter the modeled queue but are excluded from scored delay comparisons. Preserve initial/background demand in both policies.
3. Exogenous arrivals are boundary crossings, held fixed between policies. Free-flow readiness = boundary arrival +45/free-flow-speed. Free-flow speed is estimated on calibration data only. Reference approach delay = recorded intersection entry - free-flow readiness. Reference stopped time (speed <=0.3 m/s) is exported separately and must not be mislabeled as the same delay definition.
4. Use one aggregate FIFO service queue per direction; parallel lanes, lane changes, car following, spillback, and network feedback are not explicitly simulated. Discharge headway per PCU and queue startup time are fitted on calibration data only. Green plus the observed yellow clearance permits service; this approximates recorded boundary crossing during clearance.
5. For the primary counterfactual, ANFIS controls the shared east/west through green. Evaluate it separately for E and W from current modeled state and take the larger recommendation. All remaining phase durations are held at their recorded values: equivalently retain the recorded red interval between east/west through greens. Subsequent phase/green starts shift with the changed through-green duration. Repeat the median recorded red interval if the changed schedule needs an additional opportunity within the original horizon. This is a specified adapter policy, not an existing app actuation feature.
6. Recompute ANFIS inputs from each counterfactual queue as it evolves. No replay of later recorded vehicle states as if they were unaffected by the new signal. Vw and occupancy use the app's PCU/footprint definitions. Queue tail uses a calibration-derived metres-per-queued-PCU approximation, capped at 45 m. ROI width is a calibration-derived occupied lane envelope; sensitivity includes the app's default 10.5 m width.
7. Compare both policies over the same recording horizon and the same fixed cohort. Include unfinished ANFIS vehicles with delay accumulated up to the horizon, mark them right-censored, and report their number. Do not silently drop unfinished vehicles.
8. Report (a) reference delay minus modeled ANFIS delay, as the user's requested direct subtraction, and (b) modeled recorded-timing delay minus modeled ANFIS delay, which separates baseline model error from controller effects. Positive means estimated savings. Right-censored values are restricted-horizon bounds, not complete journey estimates.
9. Validate the queue model on both held-out recordings before interpreting benefit. Provisional diagnostic gate: baseline departure MAE <=5 s and >=80% of eligible reference departures within 10 s. This is an experiment-specific screen, not an industry standard. Failing it must remain visible.
10. Run service headway/startup, free-flow speed, yellow-service allowance, and ROI width sensitivities. Do not select the scenario giving the largest apparent benefit. Effects on north/south movements, turning traffic and pedestrians are unmeasured, so no whole-intersection benefit may be claimed.

Deliver reference/estimated delay for every scored vehicle, cycle inputs and recommendations, calibration parameters, validation metrics, sensitivity results, plots and a plain-language verdict. Small baseline error supports a conditional estimate only; it cannot verify the unobserved counterfactual.
